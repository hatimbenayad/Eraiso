Testing & Quality Assurance Standards (Lab S.04.01 · 17/11 Summary)

Core engineering standards enforced across every Pull Request and Maven build.

CI Enforced

RADIT Testing Workflow

  • Continuous per Iteration: Testing is executed in every UP iteration (never delayed to the end).
  • Spec-First (Topic 4.4): Design Equivalence Partitions, Boundary Values, and Error Guessing tables in GitHub Issues before writing code.
  • JUnit 6 Jupiter Only: Always import org.junit.jupiter.api.* (never JUnit 4), mirror production packages under src/test/java, use @DisplayName and Arrange–Act–Assert (AAA).
  • Coverage ≠ Quality: JaCoCo (≥75% line / ≥70% branch) finds untested paths; meaningful assertions (oracles) verify clinical correctness.

Verification Commands & Policy

  • Local Verification: Run .\mvnw.cmd clean verify (Windows) or ./mvnw clean verify (macOS/Linux) before pushing any branch.
  • Coverage Report: Inspect <module>/target/site/jacoco/index.html after running verify.
  • Zero-Bypass Rule: Never merge a PR while GitHub Actions CI is red, never use -DskipTests, and never alter an expected oracle just to pass a failing test.
  • AI Accountability (D-014): Engineers design test matrices and review every line; AI assists with boilerplate scaffolding.
