How every iteration moves from requirements to tested code across decoupled Maven submodules.

RADIT Pipeline Inside Each Iteration

  • R — Requirements: Lock exact Functional Requirements (RF) & Use Cases (CU) from the official Wiki baseline.
  • A — Analysis: Create BCE Communication Diagrams (<<boundary>>, <<control>>, <<entity>>) in Visual Paradigm (docs/diagrams/analysis/).
  • D — Design: Translate BCE models into Client & Server UML Design Class Diagrams (docs/diagrams/design/) and shared interfaces in common-contracts.
  • I — Implementation: Code services, in-memory repositories, mock adapters, and Swing UI on Git Flow feature branches (AI-assisted under D-014).
  • T — Testing: Document Black-Box Test Matrices (EP, BVA, Error Guessing) in GitHub Issues, implement JUnit 6 tests, and pass mvn clean verify + JaCoCo (≥75% / ≥70%).

Maven Multi-Module Architecture (D-017)

  • Root Aggregator (radiodiagnostics · 0.2.0-SNAPSHOT): Centralizes Java 21, JUnit 6.1.3, and JaCoCo 0.8.14 quality gates.
  • common-contracts (Built 1st): Pure Java domain entities (User, Role, Patient, ExaminationOrder), DTOs, and service contracts. Zero framework dependencies.
  • server (Depends on common-contracts): Business services (PatientRegistryService, upcoming Orders/Reports/PACS services), in-memory repositories, and Mock External Adapters (D-012).
  • client (Depends ONLY on common-contracts): Desktop Swing Views, Client Controllers, and ClientSessionContext — fully decoupled from backend internals.
